Most student resumes describe **tasks**: what you were asked to do. Reviewers are looking for **results**: what changed because you did it. The same experience can read as forgettable or impressive depending on which one the bullet shows.

## The shape of a strong bullet

A good bullet usually has three parts:

1. **An action verb** that says what you did: built, cut, shipped, automated, designed.
2. **What you did it to**, with the specific technology where it matters.
3. **The result**, with a number if you have one, or a concrete outcome if you don't.

> **Action** + **what, with what** + **result**

You don't need all three in a fixed order. You do need the result.

## Before and after

**Before:** Worked on the backend for a class project.

**After:** Built a Flask REST API with 12 endpoints and PostgreSQL for a 4-person course project; wrote the auth and search features used in the final demo.

## Where the numbers come from

Students often say they don't have numbers. Usually you do. You just haven't counted yet. Look for:

- **Speed:** load time, query time, build time, how long a task took before and after
- **Scale:** users, requests, rows of data, files processed
- **Time saved:** hours per week of manual work you removed
- **Quality:** accuracy, test coverage, bugs fixed, crash rate
- **Scope:** number of features, endpoints, screens, team size

If you truly can't measure it, say what happened concretely: "used by the club to run weekly sign-ups" is a result. "Worked on sign-ups" is not.

**Only use numbers you can explain in an interview.** If you're estimating, say "about". An interviewer asking "how did you measure that?" should get a real answer.

## Words to cut

These phrases hide what you did. Replace them with the actual action:

- "Responsible for…" → say what you did
- "Helped with…" → say which part was yours
- "Worked on…" → say what you built or changed
- "Various", "multiple", "several" → give the count

## Check each bullet

Read each bullet and ask: **"So what?"** If the answer isn't in the bullet, add it. Then ask: **"Could someone else on the team have written this exact line?"** If yes, make it more specific to your part.

Rewrite your top three bullets first, the ones a reviewer sees before they decide whether to keep reading. That's where the effort pays off most.
