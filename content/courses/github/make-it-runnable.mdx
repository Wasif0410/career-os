## Treat the README as the front door

Explain the problem and show what the repository currently does. Add a screenshot or a small example when it helps. Distinguish implemented behavior from planned features. Then give someone a realistic path to try the project.

Document prerequisites, dependency installation, configuration, sample data, the command to run it and the command to check it. Use placeholder configuration values, not live credentials. If a service is unavailable, explain the limitation and offer a local example or recorded demonstration where possible.

A diagram is useful when it clarifies data flow or boundaries. It is optional; the priority is reproducibility. Include ownership, acknowledgments and license information appropriate to the work. Follow course or employer restrictions before publishing shared material.

1. Write purpose, current behavior and known limitations.

3. Use synthetic sample data and a safe configuration example.
4. Follow the instructions from a fresh clone, or ask a peer to do so. Record every hidden assumption you find.
