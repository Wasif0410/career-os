## Tailoring is choosing relevant evidence

Read the posting and separate essential eligibility, repeated tasks and preferred extras. Check requirements such as graduation window, location and authorization through the employer's own application instructions. Do not infer that every listed tool is equally important or that missing one preference automatically rules you out.

Match the tasks to your evidence map. Reorder projects, give the strongest examples more space and use accurate terminology. If you used PostgreSQL, name it. If you only watched a course on Kubernetes, do not list it as professional experience. A skills section should describe something you can discuss or demonstrate.

Keep a master document with all truthful experiences. Make a smaller tailored version for a role family, then adjust when a posting calls for different evidence. This saves time without making every application identical.

## A worked example

One posting emphasizes data pipelines; another emphasizes user-facing APIs. Maya uses the same database project for both. In the first version she leads with input validation and reproducible imports. In the second she leads with endpoint behavior and error handling. The work and dates do not change. The order and emphasis do.

She does not add “production scale” because the employer uses that phrase. She writes that her tests used sample data and notes where larger-scale evaluation remains unfinished.
